# Лабораторная работа: Разработка интерфейса пользователя в React и интеграция с Redux Toolkit

## Тема проекта: «Компоненты распределенной системы» (System Components)

Фронтенд-приложение на **React 18**, **TypeScript**, **Vite**, **Redux Toolkit**, **React-Bootstrap** и **Axios** для каталога и интерактивной ленты компонентов распределённой серверной архитектуры (микросервисы, кэш, базы данных, шлюзы, хранилища).

---

## Реализованные требования лабораторных работ

### 1. Архитектура и управление состоянием через Redux Toolkit
- **Хранилище Redux (`src/store.ts`):** объединяет редьюсеры состояния пользователя (`userSlice`) и доменных компонентов/фильтров (`componentsSlice`). В режиме разработки подключен `redux-devtools`.
- **Срез фильтров и компонентов (`src/slices/componentsSlice.ts`):**
  - Хранит поисковую строку по названию, выбранные архитектурные слои (чекбоксы) и выбранный приоритет.
  - Содержит асинхронные Thunks: `fetchComponentsList`, `createComponentAsync`, `deleteComponentAsync`, `likeComponentAsync`.
  - **Graceful Fallback:** при недоступности бэкенда автоматически переключается на коллекцию `COMPONENTS_MOCK` из [`src/modules/mock.ts`](src/modules/mock.ts), обеспечивая бесперебойную работу в гостевом режиме.
  - Сохранение и сброс фильтров через экшены `applyFilters` и `resetFilters`.
- **Срез авторизации (`src/slices/userSlice.ts`):**
  - **Строгое соответствие методичке:** запросы авторизации и деавторизации выполнены **исключительно через прямой `axios`** без использования thunk и кодогенерации, с ручной отправкой экшенов `loginSuccess`, `loginFailure`, `logoutSuccess` в Redux.
  - Хранит флаг `isAuthenticated`, имя пользователя `username`, токен и статус загрузки.

### 2. Решение CORS и проксирование через Vite
В [`vite.config.ts`](vite.config.ts) настроено проксирование двух независимых маршрутов:
- `/api` → `http://localhost:8080` (бэкенд веб-сервиса на Go/Django REST)
- `/system-components` → `http://localhost:9000` (MinIO S3 объектное хранилище для видео и изображений компонентов)

### 3. Кодогенерация API-клиента через Swagger / OpenAPI
- Скрипт [`scripts/generate-api.mjs`](scripts/generate-api.mjs) генерирует типизированный клиент [`src/api/Api.ts`](src/api/Api.ts) с помощью библиотеки `swagger-typescript-api` на основе схемы `http://localhost:8080/swagger/doc.json`.
- Запуск генератора: `npm run generate-api`.

### 4. Разделение прав: Гость vs Авторизованный пользователь
- **Режим гостя:**
  - Доступен просмотр ленты («Лента») и каталога («Плитка»).
  - Доступна фильтрация и поиск.
  - В шапке отображается кнопка «Войти», ведущая на страницу авторизации `/login`.
  - Кнопка «Добавление» в нижней таб-панели заблокирована (`disabled`, `opacity: 0.35`).
  - Кнопки удаления карточек «✕» скрыты.
- **Режим авторизованного пользователя:**
  - В шапке отображается бейдж пользователя и кнопка «Выход».
  - В таб-панели 4-я вкладка переключается на «Выход».
  - Разблокирован пункт «Добавление» (`/add`), позволяющий публиковать новые узлы архитектуры.
  - На карточках каталога становятся доступны кнопки удаления «✕».
  - **Сброс фильтров при выходе:** при нажатии кнопки «Выход» отправляется запрос на деавторизацию (`/api/logout`), очищается сессия пользователя и **автоматически сбрасывается фильтр** (`resetFilters()`).

### 5. Блокирующая анимация загрузки
- Во время выполнения сетевых запросов (`loading === true`) поверх экрана отображается полупрозрачный оверлей `.blocking-loader-overlay` со спиннером Bootstrap, полностью блокирующий повторные нажатия кнопок пользователем.

## Структура страниц и маршрутов

- `/` или `/system-components` — **Каталог («Плитка»):** сетка компонентов с фильтрацией по названию, слоям и приоритетам.
- `/feed` или `/feed/:id` — **Лента («Подробнее»):** полноэкранный просмотр медиа (видео/фото) компонента, лайки, переход «Далее».
- `/add` или `/editor` — **Добавление («Черновик»):** 2-этапное создание нового компонента (доступно авторизованным).
- `/login` — **Авторизация («Вход»):** форма логина и пароля с переключением состояния интерфейса.

## Запуск проекта

### Локальный запуск
```bash
# Установка зависимостей
npm install

# Генерация API клиента (при запущенном swagger бэкенда)
npm run generate-api

# Запуск dev-сервера (порт 3000)
npm run dev

# Проверка типов и линтинг
npm run build && npm run lint
```
Приложение доступно по адресу: `http://localhost:3000/`.

### Запуск в Docker
```bash
docker-compose up --build
docker-compose down
```
Hot-reload поддерживается через `watch: { usePolling: true }` в `vite.config.ts`.
