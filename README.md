# Лабораторная работа №5: Разработка базового приложения на React, знакомство с жизненным циклом и хуками

## Тема проекта: «Компоненты распределенной системы» (System Components)

Фронтенд-приложение на **React**, **TypeScript**, **Vite** и **React-Bootstrap** для гостевого просмотра каталога и интерактивной ленты компонентов распределённой серверной архитектуры.

---

## Архитектурные особенности по требованиям лабораторной

1. **Управление состоянием без Redux и без React Context:**
   - Состояние общего списка компонентов (`cards`) и черновика (`draft`) хранится в корневом макете [`AppLayout.tsx`](src/AppLayout.tsx) с помощью стандартного хука `useState`.
   - Передача данных дочерним страницам осуществляется исключительно через встроенный механизм React Router: `<Outlet context={{ cards, setCards, draft, setDraft }} />` и считывается хуком `useOutletContext<AppOutletContext>()`.
2. **Получение данных из mock-объектов:**
   - Коллекция данных компонентов объявлена в [`src/modules/mock.ts`](src/modules/mock.ts).
   - Запросы к API реализованы в [`src/modules/componentsApi.ts`](src/modules/componentsApi.ts) с автоматическим переходом на mock при отсутствии связи с бэкендом.
3. **Дефолтные медиафайлы:**
   - В каталоге `public/` размещены дефолтные файлы: [`DefaultImage.png`](public/DefaultImage.png) и [`DefaultVideo.mp4`](public/DefaultVideo.mp4).
   - В mock-объектах присутствуют записи с пустыми полями `imageUrl` и `videoUrl` для демонстрации автоматической подстановки дефолтных ресурсов.
4. **Нижняя навигационная панель из 4 пунктов:**
   - Внизу экрана закреплен мобильный `Navbar` из 4 пунктов: **Лента**, **Добавление**, **Плитка**, **Вход**.
   - По заданию лабораторной для неавторизованного гостя **доступны только 2 пункта** («Лента» и «Плитка»). Пункты «Добавление» и «Вход» заблокированы атрибутом `disabled` со стилями недоступности (`cursor: not-allowed; opacity: 0.35`).
5. **Компоненты React-Bootstrap:**
   - Для построения интерфейса используются компоненты `Form`, `Button`, `Card`, `Badge`, `Spinner`, `Navbar`, `Nav`.

## Описание страниц приложения, полей и кнопок

### 1. Страница «Плитка» (Каталог компонентов)
*Маршруты: `/` или `/system-components`*

Главная витрина компонентов архитектуры в виде двуколоночной сетки карточек с расширенной фильтрацией.

#### Поля формы фильтрации:
- **Поле поиска по названию** (`Form.Control` с классом `.text-input`): текстовый ввод для фильтрации компонентов по подстроке в названии или описании.
- **Чекбоксы слоев архитектуры** (`input[type="checkbox"]` в группе `.checkbox-group`): выбор архитектурных слоев («Шлюзы», «Бэкенд», «Базы данных», «Кэш», «Хранилище»).
- **Выпадающий список приоритета** (`Form.Select`): выбор уровня приоритета обработки запросов («Все приоритеты», «Приоритет 1 (Выс)», «Приоритет 2 (Сред)», «Приоритет 3 (Низ)»).

#### Кнопки:
- **Кнопка «Применить»** (`Button` с классом `.apply-btn`): применяет выбранные фильтры с кратковременной анимацией загрузки (`Spinner`).
- **Кнопка «Сбросить»** (`Button` с классом `.apply-btn`): очищает все поля поиска и чекбоксы, возвращая полный список компонентов.
- **Карточка компонента** (`Card` с классом `.grid-card`): интерактивная карточка. При клике на карточку происходит навигация на страницу «Лента» для выбранного компонента (`/feed/:id`).
- **Кнопка удаления карточки «✕»** (`button` с классом `.delete-card-btn`): удаляет карточку из каталога с диалоговым окном подтверждения `window.confirm`.

#### Отображаемые данные карточки:
- Превью компонента (`Card.Img` с fallback на `DefaultImage.png`).
- Бейдж количества лайков (`Badge` с классом `.card-likes-badge`).
- Категория слоя (`Badge` с классом `.card-badge`).
- Название компонента (`Card.Title` с классом `.card-heading`).
- Приоритет (`.card-priority`).

### 2. Страница «Лента» (Feed / Подробнее)
*Маршруты: `/feed` или `/feed/:id`*

Полноэкранный вертикальный формат (в стиле TikTok/Reels) для пошагового изучения компонентов системы.

#### Элементы страницы:
- **Фоновое видео/изображение** (`<video className="bg-video">` или `<img className="bg-video">`): воспроизводит демонстрационное видео компонента (автозапуск, зацикливание, без звука). Если у компонента видео отсутствует или возникла ошибка загрузки, отображается фоновое изображение или `DefaultVideo.mp4` / `DefaultImage.png`.
- **Градиентный оверлей** (`.video-overlay`): обеспечивает контрастность текстовых блоков поверх видео.
- **Информационные капсулы сайдбара** (`.param-badge`):
  - Капсула **«ГРУППА»**: отображает принадлежность к слою (БД, Кэш, Шлюзы и т.д.).
  - Капсула **«ПРИОРИТЕТ»**: отображает числовой приоритет обработки.
- **Кнопка лайка** (`.action-circle.like-container`): увеличивает количество лайков текущего компонента на +1 и синхронизирует состояние в общем хранилище `cards`.
- **Кнопка «Далее»** (`Button` с классом `.next-btn` и стрелкой): осуществляет переход к следующему по порядку компоненту из массива `cards`.
- **Нижний информационный блок** (`.feed-bottom-info`):
  - Заголовок компонента (`h2.feed-title`).
  - Развернутое техническое описание роли компонента в системе (`.feed-desc-clamp`).

### 3. Страница «Черновик» (Редактор / Добавление)
*Маршруты: `/editor` или `/add`*

Двухэтапная форма создания и публикации нового компонента в системе.

#### Этап 1: Создание черновика
- **Поле «Ссылка на изображение компонента *»** (`Form.Control`): ссылка на PNG/JPG изображение.
- **Поле «Ссылка на демонстрационное видео *»** (`Form.Control`): ссылка на MP4 видеоролик.
- **Поле «Название компонента *»** (`Form.Control`): текстовое название нового узла системы.
- **Кнопка «Далее →»** (`Button` с классом `.submit-btn`): валидирует данные, формирует объект черновика `draft` и переключает форму на этап 2.

#### Этап 2: Публикация компонента
- **Карточки предпросмотра медиа** (`.media-preview-card`): вертикальный блок предпросмотра выбранной картинки и видео друг под другом.
- **Поле «Краткое описание компонента *»** (`Form.Control as="textarea"`): назначение и архитектурная роль компонента.
- **Поле «Группировка *»** (`Form.Control`): указание слоя (Кэш, БД, Бэкенд, Шлюзы и т.д.).
- **Поле «Приоритет обработки запроса *»** (`Form.Control type="number"`): числовой приоритет от 1 до 10.
- **Кнопка «Опубликовать»** (`Button` с классом `.submit-btn.publish-color`): добавляет созданный компонент в начало общего массива `cards` и перенаправляет пользователя в каталог («Плитка»).

### 4. Нижняя панель навигации (TabBar)
Компонент [`TabBar.tsx`](src/components/TabBar.tsx), закрепленный внизу экрана (`position: absolute; bottom: 0;`):

| Пункт | Иконка | Статус | Поведение |
|---|---|---|---|
| **Лента** | SVG (полосы ленты) | **Доступна** | Переход к просмотру первого или выбранного компонента в ленте (`/feed/:id`) |
| **Добавление** | SVG (плюс) | **Недоступна** (`disabled`) | Заблокировано для гостей по требованиям лабораторной работы |
| **Плитка** | SVG (сетка) | **Доступна** | Переход к каталогу компонентов (`/`) |
| **Вход** | SVG (профиль) | **Недоступна** (`disabled`) | Заблокировано для гостей по требованиям лабораторной работы |

## Запуск проекта

### 1. Локальный запуск
```bash
# Установка зависимостей
npm install

# Запуск dev-сервера (по умолчанию порт 3000)
npm run dev

# Сборка проекта
npm run build
```
Приложение открывается по адресу: `http://localhost:3000/`.

### 2. Запуск в Docker
В соответствии с разделом 9 методических указаний:
```bash
# Сборка и запуск контейнера
docker-compose up --build

# Остановка контейнера
docker-compose down
```
Приложение доступно по адресу: `http://localhost:3000/`.
Hot-reload поддерживается через настройку `watch: { usePolling: true }` в [`vite.config.ts`](vite.config.ts).
